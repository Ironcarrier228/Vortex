# VORTEX — 3D-центр визуализации данных

Windows-приложение (Win 10/11): Tauri 2 (Rust) снимает данные (сеть / диск / системный звук),
фронтенд на three.js рисует три 3D-сцены с общим рендер-слоем, bloom и «пролётом» камеры между сценами.

> Полные документы: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) · [`docs/DEPENDENCIES.md`](docs/DEPENDENCIES.md) · [`docs/ROADMAP.md`](docs/ROADMAP.md)

## Быстрый старт

```bash
npm install

# 1) Только фронтенд — в браузере, на мок-провайдерах (данные синтезируются).
#    Удобно отлаживать шейдеры/пост-обработку, не поднимая Rust.
npm run dev            # http://localhost:5173

# 2) Полное приложение (Windows): нужен Rust + MSVC build tools + WebView2.
npm run app:dev        # tauri dev
npm run app:build      # tauri build → msi/nsis в src-tauri/target/release/bundle

# 3) Необязательно: модель руки для жестов, чтобы работало без интернета.
npm run fetch:models   # hand_landmarker.task → public/models (см. «Управление жестами»)
```

Горячие клавиши: `1/2/3` — сцена, `M` — режим внутри сцены, `Space` — пауза,
`H` — HUD, `F` — fullscreen, `W` — окно вывода на второй монитор, `S` — настройки,
`G` — управление жестами (веб-камера), `Esc` — снять выделение/выход.

## Проверки без Windows

```bash
npm run typecheck     # строгие типы фронтенда
npm run smoke         # смоук-тест аудиошины, мок-сети и дерева диска (Node, без WebGL)

```

## Управление жестами (веб-камера)

Рукой можно делать всё то же, что мышью: **щипок** (большой + указательный) — вырвать узел из цепочки.
Пока держите: узел растёт для осмотра, панель сцены показывает его запросы («svchost → 93.184.216.0:443 · TCP»),
а **поворотом кисти** узел вращается; на спокойном отпускании он **остаётся** там, где вы его оставили
(кнопка «Вернуть узлы» возвращает всё в раскладку). Короткий щипок — выбрать узел, **большой палец вверх** —
действие сцены.

| Жест | Что делает |
| --- | --- |
| Щипок по орбу | вырвать узел из цепочки и перетаскивать |
| **Рывок кистью при отпускании** | **бросок**: раскрывается чёрная дыра и поглощает орб вместе со связями |
| Поворот кисти (щипок сжат) | крутить рассматриваемый орб |
| Щипок **в пустоте** | взяться за саму сцену: движение — вращение и наклон графа, поворот кисти — доворот вокруг оси взгляда |
| Щипок второй рукой | взять **второй** орб — двумя руками можно развести два узла и сравнить их запросы |
| Развести/свести две руки | масштаб; поворот двух кистей — вращение вида |
| Большой палец вверх | действие сцены (в графе сети — переключить граф ↔ глобус) |

Чёрная дыра — это «мусорка» сцены: чёрный горизонт событий, фотонное кольцо, аккреционный диск из
трёх вращающихся слоёв и искры от поглощённого вещества. Орб летит к ней по спирали, схлопывается в
точку, а все его связи рвутся с вспышкой и отлетают к дальним узлам. **Вернуть всё** — кнопка
«Вернуть узлы» или ссылка в тосте, который появляется сразу после броска.

Соединения выдёргиваются **вместе с узлом**: их точки крепления догоняют узел вяло (резинка), а если
продержать орб вырванным ~2 секунды, линия затягивается внутрь и **рвётся** — связь уходит из графа,
даже если процесс всё ещё держит соединение (это ручное «разорвать», оно живёт до «Вернуть узлы»).
Отпустили раньше — линии аккуратно выкатываются обратно к своим узлам.

Порог щипка **калибруется под вашу руку**: он считается относительно раскрытой кисти (расстояние между
кончиками пальцев делится на размер кисти), поэтому жест работает и вблизи, и вдали от камеры. Текущее
значение и порог показаны в плашке состояния — например «щипок 0.83 → нужно < 0.62»: если щипок не
срабатывает, там сразу видно, насколько не хватает.

Свайп ладонью (перелистывание сцен) и пауза открытой ладонью **по умолчанию выключены** — они срабатывали
случайно; включаются в настройках («Свайп переключает сцены», «Пауза открытой ладонью», «Кулак возвращает раскладку»).

Включение — кнопка ✋ в HUD или клавиша `G`; при первом включении Windows спросит доступ к камере.
Кадры обрабатываются локально (MediaPipe WASM) и никуда не отправляются; на паузе/свёрнутом окне камера гасится.

Без камеры (или для превью) есть демо-режим с синтетической рукой: откройте `http://localhost:5173/?hand=demo`.

Библиотека распознавания берётся сначала из локальной копии `public/mediapipe/` (её кладёт
`npm run sync:mediapipe`, он же запускается сам при `npm install`, `npm run dev` и `npm run build`),
затем с CDN — то есть без интернета и без всего лишнего приложение работает, просто без распознавания рук.
Модель руки (`hand_landmarker.task`) в репозиторий не кладётся: `npm run fetch:models` скачивает её в
`public/models/`; без неё модель подтянется из интернета при включении жестов.

### Если сцена выглядит пустой

* **«Карта сети» → глобус.** Координаты хостов появятся на этапе 3 (GeoIP, оффлайн-база MaxMind).
  До этого глобус показывать нечего, поэтому переключение в глобус объясняет причину и оставляет
  граф — он работает на реальных данных уже сейчас (кнопка «Граф», клавиша `M`).
* **Панель «Соединения»** пишет строку диагностики: сколько узлов и рёбер реально попало в 3D
  («в 3D: 37 узлов · 44 рёбер»). Если там нули — данных нет, если числа есть, а сцены не видно —
  напишите мне: значит проблема рендера, а не данных.
* **Низкий FPS при включённых жестах.** Модель и сцена делят GPU: при просадке рендера
  распознавание автоматически переходит в экономный режим (30 → 20 → 12 Гц), это видно в плашке
  состояния. Если FPS всё равно низкий — выключите жесты клавишей `G`.

### Если жестов не видно

* **Ничего не происходит после включения (✋ или `G`)?** Смотрите плашку в правом нижнем углу:
  там написано состояние распознавания и причина сбоя. Если камеру включить не удалось
  (нет устройства, доступ запрещён, модель недоступна) — приложение **само** покажет демо-руку
  и напишет, почему. Пустого экрана не бывает.
* **Видна рука, но не двигается курсор?** Держите кисть раскрытой в 40–80 см, ладонью к камере.
* **Хочу жесты совсем без камеры и без интернета:** тумблер «Демо-рука (без камеры)» в настройках
  (или `?hand=demo`).
* **Хочу офлайн на Windows:** `npm run fetch:models` — положит модель в `public/models/`
  (файл в `.gitignore`, скачивается один раз). Без него модель берётся из интернета при первом
  включении жестов: сначала Google Storage, затем зеркала на CDN npm.

## Грабли (чтобы не пугаться)

* **Остановка `npm run app:dev` через Ctrl+C** выглядит страшно, но это норма: cargo напечатает
  `process didn't exit successfully … (exit code: 0xc000013a, STATUS_CONTROL_C_EXIT)` — это код
  прерывания Ctrl+C, а не падение. Строка
  `Failed to unregister class Chrome_WidgetWin_0. Error = 1411` — тоже штатный шум WebView2
  на завершении. Настоящие ошибки приложения выглядят иначе: панику Rust видно как `thread 'main' panicked`,
  ошибку фронтенда — как оверлей Vite.
* **`npm fetch model` / `npm run fetch model`** — не сработает: нужен скрипт с двоеточием,
  `npm run fetch:models` (список всех команд — `npm run`).
* **`sync:mediapipe` не перезаписывает занятые файлы.** Если `public/mediapipe/wasm/*` держит WebView2
  или антивирус, скрипт предупредит и продолжит сборку (жесты возьмут библиотеку с CDN). Для офлайн-режима
  закройте приложение и повторите `npm run sync:mediapipe`.

## Структура

```
Vortex/
├── src/                 # фронтенд (TypeScript, three.js)
│   ├── core/            # рендер-слой, пост-обработка, HUD, переходы, транспорт, сцена-модули
│   │   ├── gesture/     # рука как указатель: MediaPipe-источник, контроллер жестов, оверлей
│   │   └── interaction/ # общий указатель (мышь + рука) и орбитальная камера
│   ├── scenes/          # независимые модули сцен: audio / network / disk
│   └── types/           # локальные типы для пакетов без .d.ts (d3-force-3d)
├── crates/vortex-core/  # чистый Rust: FFT/анализ, diff таблиц соединений, дерево диска (тесты)
└── src-tauri/           # Tauri 2: команды, события, провайдеры (wasapi/iphlpapi/jwalk), окна
```
